## Diagnostics and intentional compatibility change

- E3010: `break` outside an eligible `while` body (checker, keyword primary span).
- E3011: `continue` outside an eligible `while` body (checker, keyword primary span).
- E1101: malformed attached operands, call-like spellings and former identifier spellings (parser).
- E9004: malformed typed HIR whose Break/Continue escapes a function boundary; runtime regressions assert exact keyword spans for both effects.
- E4006: an unconditional `continue` loop exhausts the original 1,000,000-step budget. No new fuel policy or execution limit.
- Intentional Hydra 0.1 breaking change: `break` and `continue` become reserved keywords, so previous legal local, parameter and function identifiers using those words fail syntax checking. The original 0.1 test corpus remains included; no additional intentional breaking behavior.

## State-machine and exhaustive-match review

- Parser: the keyword branch advances before validating statement boundaries; `require_line_boundary` uses existing recovery; block loop retains its progress guard, EOF handling and parser depth caps.
- Checker: function entry resets loop depth; loop condition is checked before entering the new body context, and normal completion of checking restores depth. Path reachability gates effects of later operations; unreachable code is still checked. A non-normal `Never` value cannot replace the Break/Continue/Return effect identity.
- Runtime: statement producers retain keyword spans; blocks, conditions, expression operands, calls and return operands forward non-value flows; only a `while` body consumes Break/Continue. Successful iteration and Continue use the same boundary tick. Function calls restore call depth on success and errors; malformed escapes yield E9004.
- Reviewed exhaustive token, AST, HIR and runtime flow dispatch sites, and obsolete `stmt_diverges`/block `terminated` assumptions. Checker flow uses a structured outcome; the remaining lexical `terminated` identifier applies only to string literal parsing and is unrelated to control flow.
