## Reproducers, confirmed defect and disproven hypothesis

**HIGH — malformed typed-HIR `Never` index could finish as a value or bounds error.** Construct a typed HIR `Index` whose List base has `List<Int>` and valid runtime value `[7]`, but whose index expression is an `Int` literal incorrectly annotated `Type::Never`; test both index `0` and out-of-range `2` under a non-default `Span`. The accepted invariant requires a normal value emerging from a `Never`-typed index to yield internal, source-spanned **E9004**, while an actual well-typed source index outside bounds must yield **E4007**. Before the fix, the out-of-range case produced E4007, demonstrating that the static HIR annotation was ignored after normal index evaluation. Root cause: `eval_index` validated only the runtime `Value::Int` and bounds after expression evaluation, without checking the impossible normal completion of `Type::Never`. Minimal remediation in `crates/hydra-runtime/src/lib.rs`: after propagating a non-normal index flow, reject a normally returned value whose index HIR type is `Never` with E9004 at `index.span`. Added `malformed_never_index_cannot_produce_value_or_bounds_error`, observed **RED** (expected E9004, received E4007), then **GREEN** after correction. No normal source semantics or E4007 behavior changed.

**Additional regression coverage, no new semantic defects:** sibling arguments (`pair([], [])`) must diagnose the second untyped `[]` as E3015, without inheriting the first parameter's `List<Int>` expectation; a typed empty `List<Never>` compares equal to itself; a new line starting `[0]` after `let xs = [1]` is a separate List tail expression, and the declared `Unit` return of `main` makes its correct error E3002. Initial audit oracle incorrectly expected an index-related error for the latter. Source parsing proved the oracle wrong; the regression asserts E3002 and **no compiler defect is attributed** to this case. Other bounded direct CLI probes agreed with the accepted diagnostic owners.

No other demonstrated CRITICAL, HIGH or normative MEDIUM violation remained in reviewed boundaries. Non-exhaustive testing cannot prove absence of undiscovered bugs.

## Safety/resource findings and limits

List elements evaluate once, left to right. Internal values use immutable shared aggregate storage with no source-level mutation, cycles or exposure of partial List construction. Mixed List/Tuple comparison uses an iterative pair worklist with visited-pair memoization and charges existing fuel; share-aware depth checks avoid exponentially rewalking shared type graphs. NaN under physically shared aggregates is still compared on first visit and stays unequal to itself, preserving IEEE behavior. Invalid nested shapes/arguments/returns use iterative checked validation and source spans. Function call depth is restored on success, diagnostics and control-flow escape, preserving frozen D001 barriers. Ordinary negative, empty and out-of-range indexes still produce E4007. The new regression closes the malformed Never-typed index bypass.

**Boundaries:** the source contract limits literal length to 256, mixed structural type depth to 64, tuple arity to 64, parser syntax nesting to 128, expression tree to 256, calls to 128 frames and interpreter work to 1,000,000 charged steps. These controls are not a universal memory bound. Fabricated cyclic or arbitrarily large hostile Rust HIR/value graphs are outside the source-language trust boundary; the audit ran bounded malformed-HIR probes, not formal verification, exhaustive fuzzing or a multi-hour memory stress campaign. Scope excludes Set, Array, mutable List, slicing, iteration, user generics, modules, release, tags and D004.
