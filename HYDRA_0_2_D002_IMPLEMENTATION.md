## Production implementation and state-machine audit

- `hydra-ast`, `hydra-parser`: explicit tuple expression, type and projection nodes with spans, comma-sensitive parentheses, checked literal index, arity and nesting guards; all expression children participate in depth accounting.
- `hydra-lexer`: numeric scanner checks immediately preceding Dot token to preserve projection index chains and existing decimal floats.
- `hydra-resolve`, `hydra-check`, `hydra-types`: source-order tuple traversal, structural type identity and inference, E3012/E3013 projection checks, **E3014** on inferred tuple depth above 64 at the constructing expression, frozen D001 `Outcome` sequencing and whole-expression `Never` distinction. The 2026-10-08 human-approved Option A amendment retains parser E1105 for explicit annotation depth and runtime E9004 for malformed internal HIR.
- `hydra-types`: tuple structural type equality and hashing use iterative walkers, preserving field order and arity without recursive descent; diagnostic tuple-type rendering limits recursion to the accepted 64 tuple layers and renders malformed zero/over-limit arity with an opaque marker. The focused tests are `tuple_type_identity_and_hash_handle_deep_internal_structures` (1,024 nested layers) and `tuple_type_display_is_bounded_for_malformed_internal_nesting` (depth-64/65 and arity limits).
- `hydra-hir`: dedicated typed tuple construction and constant projection nodes.
- `hydra-runtime`: immutable `Rc<[Value]>` values; left-to-right strict evaluation, bounded nonrecursive opaque display/debug, checked projection, runtime HIR validation during tuple construction, projection and equality, iterative pair-memoized equality that inspects NaNs, existing fuel charging for fields and tuple pairs. A targeted malformed-HIR regression first demonstrated that a tuple construction could capture an incorrectly typed local field and return a successful aggregate; per-field runtime type validation now rejects that case with spanned `E9004`. An independent malformed-HIR regression then demonstrated that a function boundary could accept an incorrectly typed tuple parameter or return value. Runtime parameter validation before frame binding and result validation after call-depth restoration now reject both forms with spanned `E9004`; the test failed before the fix and passes after it for tuple arguments, normal tail returns and explicit `return` effects, with call depth restored. A further failing regression, `malformed_hir_projection_rejects_corrupt_unselected_fields`, exposed a projection of runtime `(Int(1), Bool(true))` with forged HIR base type `(Int, Int)` that incorrectly succeeded when selecting field zero; projection now validates the **entire** base value against the declared tuple type before selecting any field, and rejects the corrupted unselected field with source-spanned `E9004`. The binary-expression dispatch was also extracted into `eval_binary_expr` after a native-default-stack corpus test exposed a stack overflow at the existing 128-call boundary; the regression now passes on the default macOS test-thread stack.
- State checks: lexer dot state is token-local; parser guarantees bounded depth/recovery; resolver/checker preserve per-function scopes and frozen loop-control effects; tuple element early exits propagate `Flow` before later fields or aggregate allocation; call-depth restoration retains its existing runtime path; runtime error spans are retained. See `docs/STATE_MACHINE.md` for the normative transitions.
- Cargo bookkeeping: `hydra-runtime` depends on `hydra-types` at runtime, with the corresponding `fuzz/Cargo.lock` resolution entry; no new semantic dependency family.
